El **desarrollo de aplicaciones web** consiste en crear programas que se usan desde el navegador: portales de clientes, paneles internos, sistemas de reservas o productos de software.

**En resumen:**

- Una aplicación hace cosas; un sitio informa.
- Conviene cuando hay procesos, cuentas de usuario o datos que gestionar.
- Se puede empezar con una primera versión (MVP) y crecer.

## Sitio web vs. aplicación web

| | Sitio web | Aplicación web |
|---|---|---|
| **Objetivo** | Informar y captar | Ejecutar procesos |
| **Usuarios** | Visitantes | Usuarios con cuenta y roles |
| **Datos** | Poco o ninguno | Base de datos y reglas |
| **Ejemplo** | Sitio corporativo | Portal de clientes, panel de pedidos |

La frontera no siempre es nítida. Una tienda en línea, por ejemplo, tiene páginas que informan y partes que funcionan como aplicación: el carrito, el pago y la cuenta del cliente. Para ubicarte, haz una pregunta: ¿la persona viene a leer o viene a hacer algo que debe quedar guardado? Si viene a hacer algo, estás hablando de una aplicación.

La diferencia también cambia el trabajo. En un sitio, buena parte del esfuerzo va al mensaje, la estructura y el diseño. En una aplicación pesan más las reglas: quién puede ver cada dato, qué pasa si alguien se equivoca y qué debe ocurrir después de cada acción. Si quieres repasar las partes que intervienen, lee [¿Qué es el desarrollo web?](/blog/que-es-desarrollo-web).

Muchas empresas necesitan las dos cosas: un sitio público que atrae clientes y una aplicación, con acceso privado, donde se les atiende.

## Ejemplos de aplicaciones web para empresas

### Portal de clientes o proveedores

Cada persona entra con su cuenta y consulta lo suyo: pedidos, facturas, documentos o el estado de un servicio. Reduce los mensajes de «¿cómo va lo mío?» y deja una sola versión de la información.

### Panel de administración y reportes

Reúne la operación en una pantalla: pedidos por atender, inventario, pendientes de cada área. Sirve cuando hoy alguien arma el mismo reporte copiando datos de varios archivos.

### Sistema de reservas o agenda

Muestra disponibilidad, aparta el horario y evita que dos personas tomen el mismo lugar. Puede conectarse con el cobro y con los recordatorios.

### Cotizador o configurador

El cliente elige opciones y ve un precio o un rango al momento. Nuestro [configurador de proyectos web](/servicios/desarrollo-web) es un ejemplo: al elegir tipo de proyecto y funciones, muestra inversión, semanas y cronograma.

### Producto SaaS

Software que se ofrece a varias empresas desde la misma plataforma. Además de la función principal, requiere resolver el alta de cuentas, la separación de los datos de cada cliente y los cobros.

## ¿Cuándo conviene una aplicación web?

Estas son las señales más claras:

- **Tu equipo repite tareas manuales que podrían automatizarse.** Si el problema es pasar datos de una herramienta a otra, quizá baste con una [automatización de procesos](/servicios/automatizacion-de-procesos), sin construir una aplicación.
- **Necesitas que clientes consulten información propia.** Un sitio muestra lo mismo a todos; un portal muestra a cada quien lo que le corresponde.
- **Quieres validar un producto digital.** Una primera versión permite probar la idea con usuarios reales antes de invertir en todo lo demás.
- **Tus herramientas actuales no se conectan entre sí.** Una aplicación puede reunir esos datos, siempre que las herramientas permitan el intercambio.

### Cuándo todavía no conviene

No toda necesidad justifica un desarrollo. Espera, o empieza por algo más pequeño, en estos casos:

- **Una herramienta existente ya lo resuelve.** Si un software de mercado cubre tu proceso sin forzarlo, suele ser más sencillo contratarlo.
- **El proceso cambia cada semana.** Primero ordénalo, aunque sea en una hoja de cálculo. Programar un proceso que aún no está definido obliga a rehacerlo.
- **Nadie va a ser responsable.** Una aplicación necesita a alguien que decida prioridades y resuelva dudas durante el proyecto y después.
- **Solo quieres presentar tu negocio.** Para eso basta un sitio. Mira [cómo crear una página web paso a paso](/blog/como-crear-una-pagina-web).

## ¿Software existente o aplicación a la medida?

| Pregunta | Software existente | A la medida |
|---|---|---|
| ¿Tu proceso es estándar? | Buena opción | Suele ser innecesario |
| ¿Tienes reglas propias que te distinguen? | Te adaptas a la herramienta | La herramienta se adapta a ti |
| ¿Cuándo lo necesitas? | Puedes empezar antes | Requiere semanas de desarrollo |
| ¿Cómo se paga? | Normalmente una suscripción | Inversión inicial y mantenimiento |
| ¿Quién controla los cambios? | El proveedor | Tú decides las prioridades |

También hay un punto medio: conservar el software que ya funciona y construir solo la pieza que falta, conectada por API. Antes de elegir, compara el costo total a dos o tres años y no solo el de arranque.

## Qué incluye el desarrollo

El alcance cambia en cada proyecto, pero estas son las piezas habituales:

- **Cuentas y permisos:** registro, inicio de sesión, recuperación de contraseña y roles que definen qué puede ver y hacer cada persona.
- **Base de datos:** la estructura donde se guarda la información y las reglas que la mantienen ordenada.
- **Panel:** las pantallas desde las que tu equipo administra usuarios, registros y reportes.
- **Integraciones por API:** la conexión con otros sistemas, como el CRM, los pagos o la facturación.
- **Pruebas:** comprobar que cada función, permiso y caso de error se comporta como se acordó.

El proceso es el mismo que en un sitio: demo desde la semana 2, entregas semanales y código en tu repositorio. El prototipo se valida contigo antes de programar, y los cambios fuera del alcance se cotizan y los apruebas antes de construirlos. Después del lanzamiento hay 30 días de garantía sobre bugs; el mantenimiento mensual es opcional.

### Qué cuidar desde el principio

- **Seguridad:** cada permiso debe comprobarse en el servidor. Ocultar un botón en pantalla no impide que alguien llegue al dato.
- **Datos personales:** pide solo lo necesario y define quién puede consultarlo. Tu aviso de privacidad debe reflejarlo.
- **Respaldos:** acuerda cada cuánto se hacen y prueba que se puedan recuperar.
- **Migración:** si hoy usas hojas de cálculo, decide qué información pasa al sistema nuevo y quién la limpia.
- **Propiedad:** confirma que el código, los datos y las cuentas de los servicios queden a nombre de tu empresa.
- **Lo público y lo privado:** las pantallas con inicio de sesión no necesitan aparecer en Google; las páginas que explican tu producto, sí.

## ¿Y las PWA?

Una aplicación web progresiva puede instalarse en el celular y funcionar con acceso rápido. Es una opción cuando no necesitas publicar en tiendas de aplicaciones.

Se abre desde un icono, como cualquier app, pero está hecha con tecnología web. Así, una sola base de código puede atender computadora y celular. Las notificaciones y el uso sin conexión dependen del navegador, del sistema operativo y de cómo se construya, por lo que conviene probarlos en los equipos que usan tus clientes.

Una app nativa tiene más sentido si dependes de funciones avanzadas del teléfono, si el uso sin conexión es el centro del producto o si estar en las tiendas es parte de tu estrategia.

## ¿Cuánto cuesta?

El tipo "Plataforma / SaaS" parte desde $240,000 MXN + IVA; el alcance final depende de funciones, roles e integraciones. Más en [¿Cuánto cuesta una página web?](/blog/cuanto-cuesta-una-pagina-web).

Este es un ejemplo con los precios del configurador al 23 de noviembre de 2026, con hasta cinco plantillas de página y sin entrega acelerada:

| Concepto | Monto (MXN + IVA) |
|---|---|
| Plataforma / SaaS | $240,000 |
| Reservas / agenda | $28,000 |
| Integraciones por API | $34,000 |
| **Suma de los conceptos** | **$302,000** |

Para esa selección, el configurador muestra un **rango de inversión de $271,800 a $347,300 MXN + IVA**, con pago en 3 hitos y 20 semanas de entrega. Es un rango, no un precio cerrado: la propuesta se ajusta después de entender tu operación.

Lo que más mueve el costo es:

- El número de roles y las diferencias entre ellos.
- Las integraciones, sobre todo si el otro sistema está poco documentado.
- Las reglas de negocio y sus excepciones.
- El volumen y el estado de los datos que hay que migrar.
- El plazo de entrega.

Considera también los costos recurrentes: dominio, hosting, servicios de terceros y mantenimiento.

## Cómo empezar

1. **Describe el proceso que quieres resolver.** Escribe quién participa, qué hace hoy, qué herramientas usa y dónde se detiene. Una página es suficiente.
2. **Prioriza las 3 funciones más importantes.** Pregúntate qué debe existir para que alguien pueda usarla el primer día. Lo demás queda en una lista para después.
3. **Construye una primera versión.** Un MVP no es un producto mal hecho: es uno con menos funciones, pero completas. Dáselo primero a un grupo pequeño de usuarios.
4. **Mide y mejora.** Define de antemano qué vas a observar, por ejemplo el tiempo por trámite, los errores de captura o cuántas personas vuelven a usarla, y decide con eso qué sigue.

### Qué tener a la mano para cotizar

- El problema en una o dos frases y cómo se resuelve hoy.
- Los tipos de usuario y lo que puede hacer cada uno.
- Los sistemas con los que debe conectarse.
- Ejemplos de los archivos o formatos actuales, sin datos personales.
- La fecha que te importa y el motivo.

No hace falta un documento técnico. Con esa información se puede separar lo indispensable de lo que puede esperar.

## Preguntas frecuentes

**¿Qué es una aplicación web?**
Un programa que se usa desde el navegador, sin instalarlo, normalmente con cuentas de usuario, datos y procesos.

**¿En qué se diferencia de un sitio web?**
Un sitio informa; una aplicación permite hacer cosas: iniciar sesión, registrar datos, gestionar procesos o pagar.

**¿Qué es una PWA?**
Una aplicación web progresiva: se comporta como una app instalable en el celular, con funciones como acceso rápido y notificaciones, según el navegador.

**¿Cuánto cuesta desarrollar una aplicación web?**
En RankPro el tipo "Plataforma / SaaS" parte desde $240,000 MXN + IVA. El alcance real depende de funciones, roles e integraciones.

**¿Cuándo conviene una aplicación web?**
Cuando tienes procesos que hoy están en hojas de cálculo, correos o papel, o quieres ofrecer a clientes un portal propio.
